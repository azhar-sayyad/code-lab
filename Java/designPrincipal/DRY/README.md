# DRY Principle

DRY means: avoid repeating the same logic in multiple places.

If logic is repeated and requirements change, you must update many places, which increases bugs.

## Example in This Folder
`DRYDemo.java` compares:
- repeated discount logic (bad)
- shared helper method (good)

## Run
```bash
javac src/designPrincipal/DRY/DRYDemo.java
java -cp src designPrincipal.DRY.DRYDemo
```
